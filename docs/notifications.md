# 站内通知中心与邮箱接收人

通知中心入口在左侧设置上方的小铃铛，作用域是当前 Workspace。支持未读数、全部/未读筛选、分页、标为已读/未读、全部已读，以及跳转原需求会话。当前产品使用共享访问密码，已读状态同样是 Workspace 级，不是多人独立收件箱。

不接浏览器系统通知、Web Push、邮件发送或 HTTPS 改造。页面在前台时每 15 秒刷新通知元数据；离开页面后服务器仍保存结果，重新打开即可查看。

## 来源与策略

- 定时跟进：遵循每次/变化/结束策略；符合策略的结果先写入通知中心，再按配置额外发飞书。站内通知不需要机器人或接收人。
- 智能完工通知：沿用有效时长、复杂任务信号和会话范围设置，不为普通问答逐条提醒。新 Workspace 默认启用站内长任务通知；已有关闭设置保持不变。后台跟进不触发第二份长任务提醒。
- 保存的是结果摘要和投递关联，不复制原生会话历史。原文仍由 Codex Thread 管理。

## 邮箱不是邮件渠道

额外开启飞书通知后，选择机器人并填写企业邮箱。服务端使用该应用凭据调用飞书通讯录 `contact/v3/users/batch_get_id?user_id_type=open_id`，得到应用内 ID，再复用 Core 的持久化 Outbox。不会把其他应用的 Open ID 用过来。

机器人权限模板已包含 `contact:user.id:readonly`。应用还必须有接收人的通讯录可见范围。没有权限、查不到唯一用户、离职或超时均明确报错。可点“校验接收人”验证，不会发送测试消息；保存时会再次校验，投递时按当前机器人重新解析。

旧 Open ID 配置保留用于已有任务，但新页面不再要求填写。应改用邮箱；切换机器人不会静默套用旧 ID。

## 结果与投递分开

任务完成不等于飞书发送成功。小铃铛分别展示任务结果、待准备/等待投递/发送中/已发送/失败等状态；网络或权限问题不会丢掉结果，也不会把任务本身改为失败。

已授权飞书发送的意图与通知同时持久化。启动时恢复准备中/入队中的意图；如果相同 generation 的 Outbox 已存在，则只关联回执，不创建第二份。

失败后可在通知中心修正机器人和邮箱，确认后补发已有摘要，不重新执行任务；历史已完成的定时跟进也有同样入口。原失败 Outbox 在新目标有效且旧项未恢复投递时原子标记为 superseded，不能从机器人设置再次恢复。原项已发送、恢复投递或仍在重试时，拒绝产生新投递。

站内结果按来源事件/运行 ID 去重。重复事件不重置已读状态，不重发。补发只改变投递关联，不创建重复站内通知，也不改变任务完成条件、截止时间或业务结果。

首次更新不自动补发或导入所有历史消息。历史任务只有在用户明确补发该结果时才导入通知中心；不会批量外发旧消息。
