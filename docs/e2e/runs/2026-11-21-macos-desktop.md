# CodyWork macOS 客户端验收

- 日期为 2026-11-21，北京时间。
- 基线为 CodyWork `a4914c2`，Core `v0.47.0`。桌面改动在 `codex/codywork-macos`。
- 环境为 macOS 26.1 / Apple Silicon，实际 Tauri 应用与 WKWebView，Chrome 桌面与 820px 视口。使用两套隔离的生产构建、SQLite、Git Worktree、测试账号和 Codex App Server 测试进程。
- 真实 CN 仅执行连接探测并打开已有登录页。登录、工作区和会话操作均在隔离服务完成。

| 范围 | 结果 | 证据 |
| --- | --- | --- |
| 首次打开与连接校验 | PASS | 首启聚焦连接名称，非法协议有文字错误。测试本机 HTTP 成功，打开现有 CodyWork 登录表单。CN 返回需登录状态，实际登录页在桌面加载。 |
| 原生连接设置 | PASS | 用 `⌘,` 打开设置。两台同 IP 不同端口的服务各自登录并显示各自的 Workspace，切回第一台时原登录仍有效。编辑连接名称后工作区仍原样打开。 |
| 默认项和异常恢复 | PASS | 将 B 设为默认，临时切回 A 后退出，重开仍进入 B 并保留认证。停止 B 后重开显示连接错误和备用 A。取消移除仍保存 B，确认后移除本机连接并清除对应默认项。 |
| 原生会话与刷新 | PASS | 从原生工作台点击需求，发送慢请求后立即出现输入，`⌘R` 刷新后恢复同一会话和一份测试回复。 |
| E2E-001 | PASS | 错误口令提示，正确口令进入测试 Workspace，刷新重开和第二标签都保持登录。 |
| E2E-004 | PASS | 含 Workspace、Demand 和会话 ID 的地址可在第二标签打开，前进、后退和刷新恢复正确的需求与会话。 |
| E2E-007 | PASS | 慢请求即时显示且无重复，命令完成后回读保持一份，测试 App Server 中断后明确失败并提供手动重试。 |
| E2E-008 | PASS | 多轮有意相同的回复各保留一份。工具卡在所属轮次内，刷新后顺序和数量保持。 |
| E2E-011 | PASS | 双标签实时收到消息，停掉隔离服务后显示断开与重连。恢复服务后历史可读，新消息正常同步。 |
| E2E-016 | PASS | 1360px、820px 下工作台主要视图无水平溢出。覆盖桌面连接设置、弹窗取消、会话 Composer 和可见的工具箱。独立布局标签无前端 error/warn。模拟错误口令与服务中断产生预期的 401 和连接错误。 |
| 桌面发布构建 | PASS | Rust 格式检查和 2 项单测通过。发布构建为 arm64，临时签名通过 `codesign --verify --strict`。签名后的应用再次打开 CN 登录页。Apple Developer ID 公证属于后续分发步骤。 |

`pnpm verify` 通过，包含类型检查、生产构建和 487 项 Web/服务端测试。试用版保持现有服务端认证和 Runtime 路径。本轮没有复测 E2E-019 的 Codex 沙箱执行矩阵。

验收后停止隔离服务，移走测试 SQLite、Workspace、Worktree、合成适配器状态，并清理两台测试服务器的 WebKit 存储。保留签名的本机构建和 CN 连接，打开到现有登录页。
