# 需求会话自动学习 E2E 验证

- 2026 年 11 月 23 日。以 `6ffcb9a` 上的本地改动测试，CodyWebCore 为 `v0.47.0`。
- 本机使用生产构建、Chrome 1280px 和 820px 视口、临时 SQLite、两个合成 Git 仓库和本地 Codex App Server / Gemini ACP 协议测试进程。
- `pnpm verify` 通过，包括 291 项服务端测试、200 项网页测试、类型检查和生产构建。

| 用例 | 结果 | 验证内容 |
| --- | --- | --- |
| E2E-001 | PASS | 错误密码被拒绝，正确密码进入工作空间，刷新后仍恢复工作空间。 |
| E2E-004 | PASS | 另一个 Tab 直接打开同一需求会话，浏览器后退、前进和刷新后内容与选中会话一致。 |
| E2E-007 | PASS | 点「新会话」后收到一条自动学习消息。模型回复前发送问题，问题只出现一次，等学习结束后执行。 |
| E2E-008 | PASS | 学习轮及三个用户轮依次完成。刷新后保留四条独立回复与一条自动学习消息。 |
| E2E-010 | PASS | 停止正在执行的命令后显示取消。启动失败保留一个手动重试入口。 |
| E2E-011 | PASS | 两个 Tab 同步自动消息和用户消息。隔离服务重启后自动重连，Codex 原生会话的学习轮只出现一次。 |
| E2E-012 | BLOCKED | 模拟 Codex 进程退出时，页面显示失败，浏览器 WebSocket 仍连接。隔离测试进程没有真实上游 HTTPS 回退场景。 |
| E2E-015 | PASS（协议测试进程） | 从旧会话连续两次沉淀同一决策。新会话自动发起一轮读取，测试进程从现有 `docs/context.md` 取回决策。 |
| E2E-016 | PASS（受影响路径） | 查看概览、需求列表、会话、工具箱、知识库、Skills 和设置。桌面与 820px 会话均无横向溢出。 |
| E2E-019 | PASS（学习轮权限） | Codex 测试进程确认本轮使用原生只读和 `never` 审批。ACP 自动学习轮拒绝审批请求，下一轮恢复原有会话审批行为。 |
| E2E-027 | PASS（新建会话路径） | 在并行开发面板新建需求会话后，只有这条新会话发起一次学习。 |
| 运行时及触发范围 | PASS（协议测试进程） | Gemini 手动新会话自动开始并完成，刷新后继续提问未再次触发。自动创建的默认需求会话与新建 Workspace 会话均保持空白。 |

真实模型没有参与此次验证。Chrome 在故意输错密码和重启测试服务时记录了相应的 401 与连接失败，正常路径未观察到浏览器异常。

已关闭测试浏览器、服务和协议进程，并清理临时仓库、Worktree 与 SQLite。改动保存在本地，尚未部署。
