# CodyWork 自然语言 E2E 回归指南

这套用例不是浏览器脚本，而是提供给 AI 测试执行者的稳定产品契约。执行者应像真实用户一样操作页面，根据可观察结果判断通过或失败，并把发现的问题修好后重新执行受影响用例。

历史报告 [E2E_FUNCTION_REPORT_2026-08-29.md](../E2E_FUNCTION_REPORT_2026-08-29.md) 只能作为历史证据，不能代替当前版本回归。

## 怎么执行

### 1. 准备隔离环境

- 使用当前待验证代码构建并启动 CodyWork。
- 默认使用临时 SQLite 数据库和一次性 Workspace；不要把真实用户 Workspace 当成破坏性测试夹具。
- 准备至少两个小型 Git 仓库：一个干净仓库，一个包含可识别未提交文件的仓库。需要验证多仓库 Demand 时，同时选择两个仓库。
- 准备一份 Workspace 文档和两个可调用 Skill，其中一个可在测试中临时移除，用于验证失效状态。
- 记录基础 URL、代码 revision、Core 版本、浏览器、数据库路径和测试目录。

### 2. 选择用例

每次功能迭代必须执行以下 P0 冒烟用例：

- `E2E-001` 页面启动、身份验证与 Workspace 恢复
- `E2E-004` Demand 专属 URL 与刷新恢复
- `E2E-007` 用户消息立即出现、正式消息收敛
- `E2E-008` 回复完成后的顺序与去重
- `E2E-011` 浏览器实时连接与多 Tab
- `E2E-016` 页面布局、控制台与服务端健康检查

然后根据改动范围追加用例：

| 改动范围 | 至少追加 |
| --- | --- |
| Workspace、Repository、Git | `E2E-002`、`E2E-003`、`E2E-005` |
| Demand、Worktree、导航 | `E2E-003` 至 `E2E-006` |
| Composer、消息、Core reducer | `E2E-007` 至 `E2E-010`、`E2E-012` |
| Runtime、WebSocket、错误恢复 | `E2E-010` 至 `E2E-012` |
| 图片、Markdown、工具卡片 | `E2E-013`、`E2E-014` |
| 文档沉淀、新会话上下文 | `E2E-015` |
| 设置、Skill、快捷指令 | `E2E-017`、`E2E-018` |
| Skill 安装、Agent 执行面板 | `E2E-022` |
| 权限、安全边界 | `E2E-019` |
| 飞书机器人、Channel、外部消息 | `E2E-020` |
| Workspace 只读搜索会话、Workspace 飞书绑定 | `E2E-019`、`E2E-021`；有真实飞书授权时追加 `E2E-020` |

### 3. 判定规则

每条用例只能标记为：

- `PASS`：所有关键断言都有当前版本的可观察证据。
- `FAIL`：产品行为与任一关键断言不一致。
- `BLOCKED`：外部服务、权限或环境导致无法完成；必须写清阻塞点以及已经观察到的产品恢复行为。
- `NOT RUN`：未执行；不能计入通过率。

不得用“接口返回成功”“构建成功”“看起来正常”代替页面断言。涉及实时消息时，至少观察发送前、发送后未响应、响应中、结束后和刷新后五个状态中的相关状态。

### 4. 证据与报告

每次运行复制 [RUN_TEMPLATE.md](RUN_TEMPLATE.md)，保存为 `docs/e2e/runs/YYYY-MM-DD-功能或版本.md`。证据至少包括：

- 关键步骤截图或可复核的浏览器状态描述；
- 页面 URL 与可见状态；
- 浏览器 console 的 error/warn 检查结果；
- 服务端错误日志检查结果；
- 创建和清理了哪些一次性数据。

截图不要包含密码、Cookie、访问令牌、真实业务数据或个人信息。
