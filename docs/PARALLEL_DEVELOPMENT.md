# 工作空间并行开发

在左侧「并行开发」中添加需求，然后在各面板顶部选择该需求下已有的真实会话。一个工作空间最多放置 4 个需求，支持两列、三列、四宫格和临时放大。列布局单行时占满可用高度，超出列数的需求向下排列并保留面板最小高度；四宫格按 2×2 排列。手机上通过需求标签切换面板。

拖动面板标题旁的手柄可以调整展示顺序，松开后自动保存。拖动时高亮目标面板，按 Escape 或拖到面板外松开可取消。键盘可在手柄上按 Alt + 方向键移动；手机或鼠标也可在面板菜单使用「向前移动 / 向后移动」。调整顺序只移动展示位置，保留原会话和草稿；放大面板时暂停排序。

面板内的新建会话仍属于原需求，在完整需求页同样可见。面板菜单中的「打开完整需求」会进入选中的会话；「从视图移除」只改变布局，不删除需求、会话或 Worktree，也不会停止执行中的任务。

每个访问过的会话有独立的 Core 控制器、输入、图片、运行设置、审批和停止入口。切换会话会保留已挂载实例；离开页面会关闭浏览器订阅，后台任务继续。文字和图片草稿在本页面生命周期中可跨完整需求页与并行页继续使用，刷新浏览器后不保证恢复未发送草稿。

布局、需求 ID 和选中会话 ID 保存在工作空间数据库中，刷新和服务重启后恢复。不同页面同时修改布局时会显示版本冲突，点击「重新加载布局」读取已保存版本。布局目前按工作空间共享，不是每个浏览器独立的一套。

原生 Thread 是历史来源。并行页与完整需求页使用相同的 ConversationCommandGateway、事件订阅和 Core controller，不保存第二份会话记录。失败重试沿用 Core 的显式重试语义，不自动重发。

实现入口：`ParallelDevelopment.vue`、`ParallelDemandPanel.vue`、`DemandConversationSession.vue`。布局接口为 `GET/PUT /api/workspaces/:id/parallel-view`；后端验证需求和会话归属，禁止跨工作空间或跨需求绑定。
